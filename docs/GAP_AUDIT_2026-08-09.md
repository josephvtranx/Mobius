# Full-app gap audit — 2026-08-09

Four parallel deep audits over the whole codebase: (1) nav/routes/dead links,
(2) client↔server API contract both directions, (3) schema vs actual code
usage, (4) stubs + end-to-end flow traces. Everything below is verified with
file:line evidence, not speculation. Ranked by severity.

---

## P0 — Live breakages (no decision needed; fix directly)

1. **Institution registration funnel is dead.** `registerInstitution.js:6`
   declares `router.post('/api/register-institution')` while `app.js:215`
   mounts it at `/api/register-institution` → effective path is
   double-prefixed. The client POST (`InstitutionRegistration.jsx:82`) 404s.
   The entire public "Request a workspace" signup flow fails with a generic
   error. Two-line fix.

2. **No user of any role can change or recover a password.**
   - `POST /auth/change-password` exists and works — zero UI calls it.
   - `/auth/reset` stub says "ask your academy's staff" — but no staff-side
     reset endpoint or UI exists either. The advice is impossible to follow.
   - **Staff-created guardians are permanently locked out**: the link-guardian
     flow mints a random temp password (`studentGuardianV2Routes.js:85`) that
     is never surfaced anywhere (the only signal is an in-app notification
     delivered to the account that can't log in; no email template exists for
     `credentials_issued`).

3. **Profile pictures are broken three ways.**
   - `uploadService.js:44` builds image URLs on the `/api` base, but uploads
     are served at `/uploads` (not under `/api`) → in production the `<img>`
     receives index.html. When `VITE_API_URL` is unset it hardcodes
     `http://localhost:5001`.
   - Avatar vanishes on next login: none of the five login/verify/refresh
     user payloads in `authController.js` include `profile_pic_url`.
   - Settings can't show the current picture: `Profile.jsx:86` passes the
     localStorage user (no pic URL) instead of the fetched profile.

4. **Instructor-qualification management has no UI.** `classRoutes.js:78` and
   `bookingRoutes.js:70` hard-reject class creation/booking when the
   instructor lacks an `instructor_specialties` row — but the endpoints to
   grant qualifications (`POST/DELETE /subjects/:id/instructors…`) have zero
   client callers. A newly provisioned academy can be permanently unable to
   create classes. (Instructor self-registration may seed some specialties;
   staff still have no way to manage them after the fact.)

5. **Staff can see note-unlock requests but cannot grant them.** The
   instructor request side is fully wired and TaskInbox renders the task, but
   nothing calls `POST /sessions/:id/notes/:studentId/unlock`. Half a feature.

6. **`POST /api/users` would 500 if ever called.** Its INSERT omits
   `password_hash` (NOT NULL), creates no role row, no directory entry.
   Nothing calls it — either build staff user-creation properly (reuse the
   guardian-linking pattern) or delete the endpoint.

## P1 — Broken/degraded UX (quick fixes, no decision needed)

- **Fake global search** (`Header.jsx:81`): rendered for every role on every
  page, no handler at all. Remove or disable honestly.
- **Guardian notification prefs**: dropdown never reads back its saved value
  (portal payload omits `notification_prefs`; `defaultValue="all"` hardcoded);
  the PATCH clobbers the whole JSONB; the `email: true` opt-in key that gates
  the ENTIRE email pipeline (`notify.js:92`) is never writable from any UI —
  Resend transport + emailJobs are unreachable dead code; "digest" mode is
  offered but the digest job doesn't exist (silently degrades).
- **Empty states**: instructor Feedback renders blank white space for a new
  instructor (`Feedback.jsx:91` returns null; no zero-classes guard);
  SessionAttendance renders an empty roster + live Save ("0 of 0 marked");
  BookSession selects collapse to "— pick —" with no explanation.
- **Guardian dead ends**: Catalog requires typing a raw numeric student id
  (needs a child picker); guardians can never reach BookSession/StudentClasses
  (routes allow them; nothing links there).
- **Staff hidden routes**: per-student drill-downs (`/family/students/:id/*`)
  are staff-allowed but unlinked from any staff page; `/inbox` and
  `/operations/schedule` are staff-allowed, staff nav never shows them.
- **Unwired-but-built endpoints** (each needs only a small UI affordance):
  make-primary guardian; `PATCH /students/:id/purchasing` (can_purchase
  toggle); `POST /rooms` + `PATCH /rooms/:id` (rooms can be picked, never
  added/edited); `POST /payments/methods` (methods can be listed, never
  created); subject edit/delete; `GET /students/:id/guardians` (roster
  optimistically patches state instead of re-reading).
- **Cancel reasons are collected and never shown**: the guardian Report-
  Absence modal writes `session_attendance.cancel_reason/cancel_note`
  (dedicated migration) but no endpoint ever returns them.
- **Admin console nits**: `institutions.schema_version` displayed but never
  written (always NULL); `institution_settings_history` + `updated_by` never
  written by the admin config PATCH (the promised audit trail doesn't exist);
  `institutions.logo_url` fully inert.
- **Task inbox**: `assigned_to` column + `in_progress` status + `'other'`
  kind all unreachable — no claim/assign flow; membership-request
  `is_waitlist` flag is written but never read (waitlisted joins look
  identical to normal ones); `'cancelled'` status unreachable (families can't
  withdraw a pending request).
- **Full-page reload link** in finance Overview (`<a href>` instead of
  `<Link>`); ProfileCard polls localStorage every 500 ms forever + ships two
  console.logs of the full user object.
- **Messaging model gap**: contacts derive only from active *enrollments* —
  booking-only families cannot message their own instructor (and vice versa).
  (Arguably a business decision; the fix is small: include booking
  relationships.)
- **Dead code to delete**: `components/auth/BaseRegistrationForm.jsx` (fully
  orphaned), `server/src/helpers/timeSlotHelpers.js` (unreferenced AND written
  against the v1 schema — would throw if resurrected), `api.js` `auth`/`user`
  named exports (contains a `PUT /users/profile` that would hit the wrong
  route), `authService.setInstitutionCode` (calls a nonexistent
  `/api/institution`), ~10 orphaned service methods, legacy `guardianRoutes`
  v1 CRUD (superseded; kept mounted), duplicate `GET /subjects/subject-groups`
  route, stale comments (`ClassDetail.jsx:4`, `shellNav.js:4`,
  `client/CLAUDE.md` pages list).

## P2 — Dormant feature slices (need a business decision first)

- **Money-out path is schema-only**: `refunds` table (zero refs),
  `credit_ledger 'cashout'` (explicitly 400s pending Top-Up spec),
  `payments.provider/provider_ref/link_id` never written. Money can come in
  but never go out. Blocked on: Top-Up spec + processor choice.
- **Enrollment wizard doesn't enroll**: it books exactly ONE one-off session;
  `sessionsPerWeek`/`sessionCount`/package selector are display-only no-ops —
  while `POST /classes/:id/enrollments` exists and works from ClassDetail.
  Decide: is it a booking wizard (rename) or an enrollment wizard (rebuild)?
- **Time tracking**: `time_logs` is read by the staff-detail endpoint and by
  payroll, but NOTHING ever writes it — no clock-in/out feature. The staff
  hours widget is structurally always empty.
- **PA/analytics slice**: `pa_codes` write-only (captured at signup, never
  reported on); `operating_expenses` + `financial_periods` tables fully
  unused. One coherent missing feature (needs the "what is a pa_code?"
  answer).
- **Onboarding consultation**: `slot_holds.origin='onboarding_consultation'`
  + the `consultation_hold_ttl_min` knob — never produced anywhere.
- **4 dormant admin knobs**: `payment_modes_enabled`, `payment_link_ttl_hours`,
  `consultation_hold_ttl_min`, `trial_class_enabled` are editable in the new
  admin console but no business logic reads them. (The other 11 knobs are all
  consumed.)
- **Whole tables with no API**: `instructor_time_requests` (part-time
  confirmation flow), `instructor_group_specialties` (group-level
  qualifications).
- **Kakao channel** reserved, no integration. **Week browsing** in Scheduling
  honestly disabled (no date-range endpoint). **Instructor termination
  request**: TaskInbox can render the task; no instructor UI ever files one.
- `auth_logs` is write-only forensics with no attribution column (no
  user_id/email) — decide whether it should become a real security surface.
